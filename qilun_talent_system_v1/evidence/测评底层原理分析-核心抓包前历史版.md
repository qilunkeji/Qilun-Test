# 高禾人才：测评底层原理分析

核查日期：2026-09-16（Asia/Shanghai）。本版已纳入登录后的报告模板、业务脚本与离线验证，替代登录前结论。

## 一、结论

**可见实现是一套多维自陈式人才画像系统：后台提供维度分数与解释字段，报告前端进行部分衍生计算、排序、分档、图表渲染和文本拼装，再用于岗位相关展示。**

这不是仅凭官网宣传的推测：已取得企业端实际引用的数据报告、人才报告、职业定位模板及其 JavaScript。人才报告说明测评以受测者自我认知为基础，并称其量表和词条经过拆解与重构。

现阶段可以解释「有哪些模型结构」「报告怎么生成」「部分标签怎么计算」，但题目作答到原始维度分的映射、服务器计分权重、完整常模、逻辑一致性规则，以及综合人岗匹配公式仍未取得。不要把本次报告当作后台算法已完整复现。

## 二、到底测什么：七类模块

主要依据：`report-talent-template.json` 与 `report_talent-v81.js`。

| 模块 | 当前证据支持的模型结构 | 应保留的限制 |
|---|---|---|

因此，「元五人格」与「职业风格」是两个不同模块，别将整套系统简化成一次MBTI测试，也别把五因素与16型混为一谈。早期仅凭宣传图保留的模型疑问，现已通过报告模板与脚本得到更具体的结构证据。

### 1. 结果是由接口供给，而不是报告页重新给每道题打分

数据报告读取 `aggregateApi/getDataReportForQY`，人才报告读取 `aggregateApi/getTalentReport`，职业定位读取 `aggregateApi/getJuniorReportNew`。公共配置携带目标和测评版本标识；本次没有猜测目标ID或调用他人结果。

人才报告中可见的结果字段包括：

- `brandForAllP`：五因素图数据。
- `styleForAll`、`styleForTop4`：职业风格各极分数和类型信息。
- `roleForAll`、`roleForTop2`、`roleForLow2`：职业角色。
- `potentialForAll`、`potentialForAllP`、`potential5`、`potentialMs`：能力与派生指标。
- `motivationForAllHasOrder`、`motivationForAllResult`：动机分数及解释条目。
- `valueForAll`：价值观。
- `advantageForAll`、`advantageForAllP`：才干明细与类别。

**这些是当前脚本使用的字段名，不是本次已拿到的真实受测者JSON数据。**

### 2. 大量解读采用既定章节与字段拼装

例如，前端将 `resultAdvantage`、`resultWeakness`、`resultManage`、`introduce` 等字段插入优势、弱项、管理建议等位置；部分动机等级说明直接保存在脚本里。

这支持「模板化章节＋结果字段＋规则化解读」的实现判断。后台解释字段究竟来自固定知识库、其他计算过程或生成服务，前端材料不足以完全区分；当前也没有证据把它描述为实时大模型综合判断。

### 3. 0～100是报告所采用的量尺，不是正确率或成功概率

模板将职业角色划为三个区间：0～60、61～80、81～100；将能力和动机划为四个区间：0～40、41～60、61～80、81～100。

这些分档能说明页面如何解释数值，并未说明题目原始分怎样换算成该量尺。分数对应岗位表现的预测意义，需要另外的效度证据。

## 四、已复现的具体规则

以下为所下载原始函数的逻辑整理，不是以通用心理学公式代填本站实现。

### A. 四类驱动倾向：两项相加，取最大组

`report_talent-v81.js` 的 `buildMotivation` 对八项动机分做以下组合：

```text
安乐 = 享受 + 健康
归属 = 情感 + 荣誉
权利 = 权力 + 财富
成就 = 工作 + 创新

驱动倾向 = 四组总分中的最高组
```

其中「权利」是输出标签，「权力」是基础动机名，保留其实现中的区别。代码对四组求和结果排序并取末项；并列最高时也会显示一个标签，不宜据此理解成统计上显著的差别。

离线测试验证了四类分别胜出，以及只改变「财富」一项时，输出由「成就」切换到「权利」。这是展示层衍生分类，不是题项计分公式。

### B. 工作投入度与驱动能量：组合计算后按配置分档

同一个函数还进行如下计算，公式中的输入均为后台返回的八项动机分：

```text
W = (财富 + 工作 + 创新 + 荣誉 + 权力) / 25
L = (健康 + 享受 + 情感) / 15
Δ = W - L
投入指标 I = Δ × (1 - k) + W × k
```

实现先将 `W`、`L`保留两位小数，再计算差值。`k`按差值绝对值分段：

| 条件 | k |
|---|---:|
| 0 ≤ abs(Δ) ≤ 1 | 0.2 |
| 1 < abs(Δ) ≤ 5 | 0.3 |
| 5 < abs(Δ) ≤ 10 | 0.4 |
| abs(Δ) > 10 | 0 |

随后，用后台提供的 `motiveOccupation` 阈值对 `I` 分档；将八项动机分总和与 `motiveEnergy` 阈值比较，输出驱动能量等级。两个阈值配置的线上实际值未取得。

注意：脚本还算了若干指针坐标，其中一些未在这一函数后续写入可见控件。这里不将未使用的中间变量当成已生效的额外测量模型。

### C. 才干图：按输入列表前16项进行类别汇总

`reportUtil-v81.js` 的 `buildTypeBParentPercent`：

1. 建立四类才干的汇总项。
2. 只处理明细数组中索引0～15的条目。
3. 按 `pid` 匹配所属类别，将各条目的 `value` 相加。
4. 去掉总和为0的类别，然后交给饼图显示占比。

函数本身没有对传入数组排序，因而严谨表述是「输入列表前16项」，而不是凭此断言它独立找出了分数最高的16项。离线加入第17项且赋很大数值，四类合计保持不变，符合源码条件。

此外，人才报告的能力章节会按 `value` 降序排序，选择前6项和末3项；才干章节按返回顺序突出前6项和末6项。数据报告和人才报告对后段项目的选取并非处处相同，旧字段名也不必然等于当下可见项目数。

### D. 职业风格：比较每对倾向，风格详情由后台字段供给

`buildStyle`比较8个倾向分数中的相邻两项，用较高项的名称和字母作显示。类型介绍、适合职业等则来自 `styleForTop4`、`styleForTwoCard` 等结果字段。

这能解释四对倾向与16型呈现结构，但不揭示具体题目如何计入E、I等基础分，也不证明其采用某一原版量表的完整规范。

## 五、需要特别核查：「大数据平均值」是固定前端参考

人才报告模板将五因素平均值解释为系统受测者的统计均值；但数据报告与人才报告的 `buildYuanWu` 实际都在函数内部构造固定参考数组：

```js
[20, 20, 20, 20, 20, 0]
```

- 图例将这个数组标为“大数据平均值”。
- 各维度实际值由 `brandForAllP` 提供。
- 人才报告中高于或低于平均值的解释，也将个人值与此数组按索引比较。
- 五个因子的模板说明与六个数组元素并存；末位0怎样与具体载荷配合，尚缺实际报告样本，不将其解释成已确认的第六人格因素。

另检查了页面引用的`total4.js`：`myBuildChart`仅补充字体配置后调用`setOption`，不替换该参考数据。用两组不同的合成人格分数执行原始函数，参考数组保持不变，生成的高低描述也按固定参考值变化。这一行为已经离线复现。

**可下的结论：此报告函数不是每次从接口读取实时全站均值再画参考线。**

尚有多种解释：可能是以20为中心的标准化量尺、固化的历史参考值，也可能是说明文案与实现未同步。仅凭该前端事实，尚不足以认定全站后台没有常模、分数随机生成或整体测评无效。

## 六、逻辑一致性与人岗匹配：可见什么，缺什么

### 逻辑一致性

列表和报告公共脚本显示 `logicDegree`：0为高、1为吻合、2为低、-1为缺省显示；低等级时还会改变参考价值提示。后台也提供耗时字段。

这只能证明存在质量提示及相关字段。是否使用重复题、反向题、异常耗时、量表间矛盾或其他规则，当前都未验证；不将其称作已经还原的测谎算法。

### 人岗匹配

宣传资源显示岗位模型与批量匹配能力。报告模板说明默认报告会被用于建模和匹配，未设置时使用最新版本。因此测评结果确实被设计为岗位业务的输入。

但是，没有拿到一个真实岗位模型与对应匹配输出，尚无证据决定最终采用加权距离、区间命中、角色映射、数据拟合或怎样组合。登录前报告中的示例匹配公式仅是解释示意，本版不再将这些示例放在实际实现链路中。

## 七、怎样理解其科学性

当前证据足以说明工程结构，不足以替代心理测量验证。尤其应区分：

- 自我认知问卷产生的人才画像，与工作实操或岗位绩效的直接测量。
- 页面提供的分档，与真实存在的常模、误差范围及效度证据。
- 解释性文本或岗位建议，与已经校准过的录用成功概率。

本站报告指南自身强调个人状态会影响结果，倾向于解释同一人的内部特征分布，不建议直接据各项数值横向比较不同受测者。这里将其记作产品自己的使用说明，不替其背书。

进一步判断质量，最有价值的是量表与题项说明、常模与标准化方法、信度效度报告、岗位模型样本及匹配分定义。当前套餐状态与空记录限制了真实输入输出取证；即使后续取得报告，也仍要分别验证服务器未公开的步骤。
