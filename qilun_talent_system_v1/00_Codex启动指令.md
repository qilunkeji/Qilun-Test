# 可直接交给Codex的开发总指令

请在我的真实工作区内开发「齐论AI人才管理系统」。这是实际软件开发任务，不是只给方案、界面截图或静态演示。系统需要电脑管理后台、独立H5答题入口、岗位与人才库、受控渠道接入、测评框架、面试分析和按功能配置的大模型服务。

## 一、先读文档和检查项目

请依次完整读取：

1. `docs/01_完整产品与工程需求.md`
2. `docs/02_测评证据与兼容边界.md`
3. `docs/03_验收与开发阶段.md`
4. `docs/04_AI智能体提示词.md`
5. `docs/05_来源与设计决策.md`
6. `schemas/`、`examples/`，以及 `evidence/` 中五份原始文稿。

检查现有代码、依赖、数据库迁移、身份认证和运行方式；先记录可复用部分，再决定增量实现。没有仓库时再按方案推荐架构建立新项目。未经确认不删除现有目录、不重建生产数据库、不替换现有账户体系。

原文稿里的本地JS/JSON路径不一定存在。实际检查后列出找到与未找到的原件，不凭路径名称认定已经取得。历史分析中的示意公式不能用来补齐缺失的原站算法。

## 二、按完整业务闭环实现

核心流程：

岗位创建/同步与优化 → 简历授权接入/导入 → 解析去重与岗位证据比较 → 人工审阅 → 从候选人与岗位生成个人H5邀请 → 手机作答或授权外部报告导入 → 测评报告 → 面试提纲 → 上传录音/文稿 → 面试证据分析 → 人工下一步 → 按授权用途和保留期限进入人才库或员工发展档案。

员工测评不强制关联招聘岗位。候选人和岗位是多对多关系，每次申请独立状态；不能将一次未邀约等同此人永久淘汰。

H5不是后台手机版。收件人无需后台账户，使用专属受限会话答题；链接预览不消耗名额，绑定人员及版本，支持弱网恢复、幂等提交、到期/撤回、本人报告与内部报告字段隔离。

## 三、不得用假实现代替依赖

完整题库、逐题计分、常模、岗位标杆聚合、正式匹配算法缺失时，正式规则包必须阻塞发布。不要让LLM猜题、编分、填固定百分比，或把3道题说成完整64题。可以完成框架、授权报告导入和明确标识的演示流程，不阻塞其余招聘功能。

BOSS等平台按已核验能力接入；没有平台允许的通道时，交付适配器接口、待授权状态与人工导入。插件不能绕验证码、躲配额、偷取Cookie、读取隐藏信息或自动发送邀约。500份/日是内部目标，不是已取得的外部配额。

不得生成基于MBTI、性格、年龄、婚育、照片外貌等因素的招聘排序、录用/淘汰或岗位安排。保留工作相关证据、未知项与人工复核。自述性格和测評偏好另行管理，不假装已验证能力。

## 四、AI与计分必须分离

固定测评计分使用服务端版本化规则或授权引擎；LLM只解释已取得结果，不改基础分。按功能设置模型、Key引用、提示词、预算、超时、备用策略、输出Schema及数据地域限制。

全局配置可被功能配置覆盖。供应商密钥只由服务端秘密存储读取，不返回PC、H5或插件。没有Key时基础业务可用，AI按钮显示未配置；mock输出必须显著标识。

所有AI结论包含可验证材料引用；检验引用存在、说话人正确、数值一致。简历和面试文稿中的指令视为不可信文本。模型不能自主发消息、发布岗位、决定录用或跨租户查数据。

## 五、工程交付

实现真实数据库和服务端API，而非仅在浏览器内存保存。具备租户/对象权限、私有文件访问、任务队列、重试、幂等、版本、审计、保留删除闭环和费用台账。数据库结构、API契约和状态机先一致再写页面。

不要把所有功能塞进一个组件或一个万能智能体。依赖选型先核验当前稳定版本，锁版本；复用既有项目的合理技术栈。缺少原站规则、模型Key或外部授权只阻塞对应依赖，不反复要求我确认已写明的普通页面与业务规则。

按验收文档的阶段推进。每阶段先实现、再运行能运行的测试和构建，再修复；不得只停留在计划。遇到真实阻塞，继续实现不依赖它的部分并记录。

阶段完成后说明：改了哪些文件、运行哪些命令、实际通过/失败的用例、未测项目、需要我提供的具体外部材料。截图只是补充，必须有真实数据/API/权限流程。

最终提交应用源代码、迁移、环境变量模板、运行与部署说明、虚构种子数据、接口文档、自动化测试、验收记录、依赖/授权待办和回滚办法。没有运行的测试写“未运行”，未接入的平台写“未接入”，未取得的计分规则写“缺失”。
