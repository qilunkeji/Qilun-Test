## R：公开官方资料与本项目采用的约束

### R1：个人信息保护与自动化处理

《中华人民共和国个人信息保护法》官方全文，国家统计局网站转载：

`https://www.stats.gov.cn/gk/tjfg/xgfxfg/202503/t20250310_1958923.html`

本方案据此要求核实处理目的和依据、最短必要保存期限、告知及权利响应，并对自动化决策等适用场景进行影响评估。特别涉及第19条保存期限、第24条自动化决策、第27条已公开信息、第28—29条敏感信息、第38—39条跨境处理及第55—56条影响评估。

法律适用必须结合真实运营主体、人员所在地、招聘和劳动关系、数据类型、供应商与传输路径判断。本方案是工程控制设计，不代替上线前对具体处理活动的法律审查。

### R2：MBTI用途

The Myers-Briggs Company，MBTI Facts：

`https://www.themyersbriggs.com/en-US/Support/MBTI-Facts`

提供方说明MBTI不应用于招聘甄选或岗位安排。因此本项目把自陈偏好与招聘证据分开，而不是将类型换算成“岗位适合度”。高禾的职业风格模块只是已知为MBTI式结构，不因此被认定为正式MBTI问卷。

### R3：BOSS接入状态

BOSS直聘官方首页及其协议入口：

`https://www.zhipin.com/`

`https://about.zhipin.com/agreement`

本轮可定位官方入口，但未取得足以核实账号具体API权限、批量导出授权或无人值守插件许可的完整材料。不能据此断言“所有自动化一律可用”或“该账号已经获准”。适配器维持待授权，具体能力凭平台确认和合同/产品授权联调。

### R4：浏览器扩展任务生命周期

Chrome Extensions官方文档：

`https://developer.chrome.com/docs/extensions/develop/concepts/service-workers`

`https://developer.chrome.com/docs/extensions/develop/migrate/to-service-workers`

扩展Service Worker具有事件驱动和休眠生命周期，因此设计需持久化任务、断点恢复和设备在线状态；不能依赖永久内存循环，也不能在电脑离线时宣称仍通过该浏览器采集。

### R5：API Key安全

OpenAI官方说明：

`https://help.openai.com/en/articles/5112595-best-practices-for-api-key-safety`

其建议不要将Key部署在浏览器或移动端，使用服务端与安全的秘密管理。本项目采用秘密引用、独立权限、轮换、脱敏日志，而不是把各功能Key直接塞进网页配置。

### R6：结构化输出边界

OpenAI Structured Outputs官方文档与说明：

`https://developers.openai.com/api/docs/guides/structured-outputs`

`https://openai.com/index/introducing-structured-outputs-in-the-api/`

JSON Schema可以约束输出结构，不等于验证内容事实。系统仍需校验证据、对象权限、数值与业务状态；供应商拒绝、截断或不支持Schema时单独处理。

### R7：队列

NestJS官方Queues文档：

`https://docs.nestjs.com/techniques/queues`

本方案采用异步队列处理简历、长音频、报告和重试。选择NestJS/BullMQ是本项目建议，不是原测评站技术栈的取证结论。

### R8：数据库隔离

PostgreSQL官方Row Security Policies文档：

`https://www.postgresql.org/docs/current/ddl-rowsecurity.html`

行级安全可作为隔离层，但特权角色和表所有者等存在绕过路径。应用对象权限、最低数据库权限和隔离测试仍不可少。

## 新系统设计，而非原站事实

以下均为本项目建议：技术栈、导航、UI建议色、表结构、API、权限、H5邀请安全机制、预算预留、保留清理、工作相关证据标准、阶段拆分、性能测试目标。没有对原站“已实现同样功能”的暗示。

500份/日来自用户需求，是内部处理目标；100个H5并发、10万虚构人才以及P95目标是拟定验收条件，不是已测成绩。没有推荐固定最新模型或填写未经核实的模型价格。

## 交付前仍需确认的项目输入

| 项目 | 缺失时的工程处理 |
|---|---|
| 现有仓库、技术栈、部署环境与统一登录情况 | 先检查，能复用则复用；禁止破坏性替换 |
| 正式岗位和岗位标准 | 可用虚构种子数据验证功能，真实筛选前由HR确认 |
| 正式题库、计分映射、常模、授权范围 | 测评规则发布阻塞；交付框架和授权报告导入 |
| 实际可用的外部测评API及其合同权限 | 接入状态为未配置，不编造回调或参数 |
| 完整真实答案—结果样例及其版本 | 不宣称分数与原站完全兼容 |
| 招聘平台对接渠道、配额和许可 | 交付适配接口及人工导入，不实际批量采集 |
| 模型供应商、真实Key、数据地域、计费表 | 基础功能可用，付费AI任务阻塞并明确提示 |
| 人才储备期限、退出渠道、录音与发展测评告知 | 提供配置与流程，未确认用途不无限存储 |
| 正式VI、域名、短信/通知配置 | 使用可替换变量，不冒充现有已接通服务 |

这些缺项应在管理后台和交付报告中可见。属于单一模块的阻塞，不应成为停止整个招聘系统开发的理由。
