# 测评证据与兼容边界

本文件只整理用户给出的证据，不补写高禾后台算法。与主需求中的新系统设计分别使用。文稿所称“已验证”指原调查记录中的验证，不代表本交付包重新执行了那些脚本。

| 编号 | 原文件 | 使用方式 |

| E1 | 逐题计分与匹配总分-续查实证.md | 最新续查，新增手机报告衍生规则；核心计分依旧未知 |
| E2 | 核心计分与岗位匹配-抓包分析.md | 答案编码、题型、岗位输入、正式与辅助匹配区别 |
| E5 | 测评底层原理分析.md | 当前综合结构、报告数据字段及PC报告规则 |
| E3 | 测评底层原理分析-核心抓包前历史版.md | 历史记录，不能覆盖后来的真实三题证据 |

这些材料全部保留原文在 `evidence/`，使用原件SHA-256核对。后续提供新材料时新增证据，不能重写历史文件来掩盖未知项。

历史状态更新不意味着不同页面的不同公式可以混用；PC和手机规则应分别建档。

## 2. 现有材料能确认什么

材料记录的实际类型配置为职业定位64题；真正取得的不同题目仅944、943、942三道，类型均为A/B双陈述。更改类型/页码仍返回当前类型和这三题，原因未确定。五份分析文稿并不提供完整64题的所有题干、选项及计分键。[E1 §二；E2 §一]

可确认A/B题的提交选项编号为1、2、3、4、5；单陈述型前端编码方向为5、4、3、2、1。编码只是“选了哪一项”，不代表该题加多少分。[E2 §二]

价值观前端流程：64词分4组、每组选5、20中选10、10项排序。未知完整词库与排名权重。文稿提及隐藏节点与可见排序节点可能不同步，仅为待线上验证点，不能断言正式结果已错误。[E2 §二.4]

岗位建模前端输入：名称、行业、适用岗位、1～5名优秀员工、业绩说明。后台如何聚合这些人未知。匹配报告直接读取服务端的综合分和四项分，不在前端通过四项平均计算总分。[E2 §三、五]

材料描述一套七模块的自陈式人才画像，不是单独一次正式MBTI测试，也未证明其使用任何特定商业量表的完整原版。[E5 §二]

## 3. 不可以宣称已得到的部分

| 环节 | 缺失内容 | 对开发的影响 |
|---|---|---|
| 完整题库 | 全部题干、选项、分组、排序约束与版本 | 正式原版答题不可发布 |
| 逐题计分 | 每选项对应维度、正反向、跨维度、权重 | 不能从答案计算原版维度分 |
| 标准化 | 原始分换算、常模样本和版本 | 不能声称分数是百分位/能力概率 |
| 质量检查 | 后台一致性规则 | 不做“测谎已还原”宣称 |
| 岗位建模 | 标杆聚合、缺失值/异常值处理 | 不自行假定均值是原规则 |
| 分项匹配 | 正式后台函数 | 辅助函数不能替代 |
| 综合匹配 | 权重、门槛、惩罚、截断、舍入顺序 | 不自行填25%或40%权重 |
| 真实样本 | 完整答案—维度—模型—匹配结果链 | 不能端到端核验输出相同 |
| 文本解释来源 | 服务端文本是否模板/生成以及完整内容 | 不能承诺全部文字逐字一致 |

E4中的 `6-x` 反向计分示例与加权距离示例均已明确是说明用假设，不得导入正式引擎。

## 4. 已知报告衍生规则必须按页面隔离

### 4.1 PC人才报告适配器：`gh_talent_web_v81`

依据E5 §四（及E3中相同层次的记载）：八项动机输入来自报告接口；基础分如何计算仍未知。

```text
安乐 = 享受 + 健康
归属 = 情感 + 荣誉
权利 = 权力 + 财富
成就 = 工作 + 创新
```

比较四组总和，显示最高组对应解释。“权利”是输出标签，“权力”是基础维度名，不自动校正成同一个字段。并列最高时原代码排序行为不等于统计上显著差异，也不证明后台有某种平局规则。

```text
W = (财富 + 工作 + 创新 + 荣誉 + 权力) / 25
L = (健康 + 享受 + 情感) / 15
W、L先各按JavaScript toFixed(2)处理
D = W - L
I = D × (1-k) + W × k

abs(D) ≤ 1       k = 0.2
1 < abs(D) ≤ 5   k = 0.3
5 < abs(D) ≤ 10  k = 0.4
abs(D) > 10      k = 0
```

I的分档参数由对应接口配置提供，PC的实际参数未取得。不要拿手机模板参数默认替代。末段k=0是原记录行为，不能为了“更合理”偷偷改掉。

### 4.2 手机高级报告适配器：`gh_phone_senior_v81`

依据E1 §四：图表读取 `datas.motivationForAll`；下述计算读取 `datas.type4Result`。本轮没有真实高级报告业务数据，不能假定两数组相同。

```text
W = (财富 + 工作 + 创新 + 荣誉 + 权力) / 5
L = (健康 + 享受 + 情感) / 3
W、L先各按JavaScript toFixed(2)处理
D = W - L

D > 1       工作倾向说明
-1 ≤ D ≤ 1  兼顾说明
D < -1      生活倾向说明
```

职业投入度 `R = D × (1-w) + W × w`，w分段同上述0.2、0.3、0.4、0。手机模板本次参数：

```text
motiveOccupation = "21.6,6.1,3.6,0"
分档：R<0；0≤R<3.6；3.6≤R<6.1；R≥6.1

motiveEnergy = "637.5,472.5,375,257.5"
S = type4Result遍历到的value之和
分档：S<257.5；257.5≤S<375；375≤S<472.5；S≥472.5
```

21.6和637.5还参与最高档指针坐标换算，不是岗位权重。本次模板值不能推广为全账号、全页面、全后台版本固定常数。

两个页面除数差5倍是已记录差异，但来源数组、量尺关系未核实。禁止自动归一化后声称“其实是同一个公式”。接入真实数据时必须声明页面适配器和量尺；无法识别则阻止衍生计算。

### 4.3 仅保留作证据的单项辅助函数

依据E2 §四：

```text
x < m：  S = 85 × x / m
x ≥ m：  S = 85 + 15 × (x-m)/(U-m)
角色/能力 U=100；动机/价值观 U=20
然后钳制0～100，再toFixed(0)
```

原调用点丢弃S，表格显示服务端传入分数b。不能把该公式投入正式招聘匹配。`x=m=U`时原函数会出现NaN的离线测试结果，不意味着在线页面真实显示NaN。

### 4.4 已知展示阈值

综合分：≥85“非常符合”，70～<85“比较符合”，50～<70“基本符合”，<50“不符合”。分项分的第一档从80开始，其余70、50相同。[E2 §五]

这些阈值只说明原站如何显示已返回的分数，不说明总分算法或招聘预测效度。新系统如展示外部原报告，应注明外部原始标签，不将其直接接成自动拒绝/录用动作。

### 4.5 固定参考线

原报告代码内构造 `[20,20,20,20,20,0]`并标“大数据平均值”，不能据此前端代码证明其为实时全站统计或证明全站没有常模。[E5 §五]

兼容资料可保留原行为；新系统没有常模依据时不能自行生成“大数据平均值”。需显示为外部模板参考或不展示，公开说明与原展示有何不同。

### 4.6 才干与排序

类别饼图汇总输入列表索引0～15，并未在该函数内排序；不能说函数独立挑出最高16项。能力、才干不同报告的前后选取也不同，应随报告适配器配置，不以一个通用“TopN”覆盖全部原逻辑。[E5 §四.C]

## 5. 从输入到输出的兼容验证

每个授权测评版本需完整定义：题目/选项映射、维度原始分、转换规则、常模、质量规则、解释模板、输出字段和报告适配器。

黄金用例至少含：包版本、全部输入答案、原引擎结果、预期维度、预期类型、预期衍生标签、岗位模型输入、预期分项与总分、解释字段及来源证明。一个孤立PDF无法唯一证明后台函数。

测试分层：编码与保存协议测试；纯函数与边界测试；原始分与转换测试；真实完整样本测试；H5和报告端到端测试。合成分数只用来测展示，不写成真实受测者结果。

测试通过的表述应是“授权版本X的规则与这些样本通过一致性检验”；若取得完整规则并覆盖发布范围才按合同定义验收。有限样本相同不证明未知后台全域100%相同。
