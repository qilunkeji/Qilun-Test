# 项目组与独立测评（本地实现，尚未上线）

## 使用流程

- 人才档案与测评中心共用项目组名称，但每份档案、每次测评各自归类；测评分组不会自动修改人员的项目组。
- 可新建项目组，并在“全部项目组 / 未分组 / 指定项目组”之间筛选。人才姓名搜索保留跨项目能力；选择“全部项目组”即可。
- 发起测评时选择“内部人员”或“外部 / 独立测评”。内部选择现有人才档案，外部可以不绑定；有档案的外部参与者也可以直接关联。
- 每份新测评均需本人填写姓名、手机号、出生日期。个人资料加密保存；报告手机号脱敏。同一份中断续答保留资料，不反复清空。
- 未绑定测评可在答题前或完成后，由 HR / 人才负责人核对身份并明确确认关联已有档案。不按同名自动合并，不自动创建虚构简历或人才档案。
- 关联后可从人才档案打开测评报告；同一人员的岗位面试可选择已关联的测评。已绑定记录不能二次改绑。
- 测评记录按100条分页，不限制在前100条。每个专属链接对应一份答卷，不能拿同一链接同时收集多人的答卷。

## 数据与权限边界

追加迁移 `011_project_groups_independent_assessments.sql`，不修改001–010已应用迁移。旧记录默认内部、未分组，不改写答案、报告、个人资料、模型参数或规则指纹。

后补关联写入独立的 `assessment_archive_bindings` 表；原邀请的 candidate_id、application_id、题卷及凭据仍受原不可变触发器保护。关联或分类不会重新计分。项目组调整要求提交原分组，冲突拒绝覆盖。所有查询和写入校验服务端租户与角色，并留下不包含资料正文的审计。

独立记录保留365天，答题链接仍按创建时的1–30天有效期限制访问；过保留期不能通过关联新档案恢复访问。绑定后还受人才档案的保留期限制。访问到期不代表物理删除；授权负责人仍可按既有删除流程处理。

历史邀请沿用旧资料要求；新邀请在服务端强制校验姓名、手机和出生日期。逻辑一致性依然保留“未评定”，没有伪造缺失的评分规则。
