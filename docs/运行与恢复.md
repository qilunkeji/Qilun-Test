线上验收记录已撤销/删除，独立停机备份后按精确ID清理虚构人员，确认用户1、人员0、答卷0，原线上管理员和密钥保留。随后正常重启并复核公网登录。浏览器控制工具反复未响应；手机响应式页面已有实现，未完成实际浏览器/微信视觉验收，不能把接口验收当作视觉验收。

## 当前边界

P1 使用 Node.js 24 + Express + React/Vite + PGlite，选择嵌入式 PostgreSQL 是因为本机没有 Docker/独立数据库，便于实际执行与测试。与建议的 NestJS + PostgreSQL 服务 + Redis/BullMQ 相比，API 框架和本地数据库运行方式有明确调整；尚未实现 Worker、Redis、对象存储和 Docker Compose。它们是后续工程工作，不是仅等待 Key 即可运行的功能。

此版本拒绝 production 启动，只监听回环地址。不要端口转发或放到公网。生产化前需要服务端数据库连接适配、最小权限运行账户/RLS、完整组织对象授权、秘密服务、TLS、会话及登录限速共享存储、备份与删除抑制、部署构建与恢复演练。

## 迁移与恢复

`infra/migrations/001_foundation.sql` 首次启动由 `openDatabase` 在事务中执行，schema_migrations 保存版本和 SHA-256。再次启动校验一致性，已应用文件变动会停止启动；不要改写已应用迁移，新增后续迁移。当前脚本没有自动 DROP 或 down 迁移，避免不可逆丢数据。

恢复策略：先停止本地 API（Ctrl+C），备份整个 `.local/database` 目录；加密密钥在受控位置单独备份，不与业务库打包共享。回滚版本前，将数据库备份复制到一个**全新目录**，保持原目录不动，再将 DATA_DIR 指向恢复目录并使用与迁移相符的代码。确认验证后再开放访问。

自动化测试实际执行：独立临时库写入虚构租户 → 正常关闭 → 从磁盘重新打开 → 重复迁移校验 → dumpDataDir → 从 dump 创建新实例 → 核验原记录。该演练只验证 PGlite 文件/快照恢复，不代表已做生产 PostgreSQL 备份、异机容灾或含删除抑制记录的恢复。

## 秘密与账户

首次初始化生成随机 local-admin 密码，账号角色 talent_lead，明确有本地业务授权，不把运维角色当全权限管理员。`.local/initial-access.txt` 为本地交付访问文件，阅后由使用者妥善保管；不上传 Git 或云服务。已有账号时 init 不重置密码。P1 没有自助密码重置、OIDC、用户禁用或成员管理界面。

CONTACT_ENCRYPTION_KEY 是 32 字节服务端 AES-256-GCM 密钥，租户 ID 为认证附加数据。切勿删除或无迁移直接替换该密钥，否则已有联系方式不可解密。当前仅本地开发秘密文件，尚非托管 KMS。AI API Key 的存储与轮换在 P3 实现，P1 不接收也不返回模型 Key。

## 数据保留

必填用途、依据、期限，过期后列表/详情/原文/联系方式/API 关联全部拒绝访问。当前**没有物理删除**，没有向量、缓存索引和外部委托清理流程；因此不能用于真实数据的完整删除合规验收。后续应建立可审计 erasure jobs、备份抑制和恢复前重放，不能把到期隐藏当作完成删除。
