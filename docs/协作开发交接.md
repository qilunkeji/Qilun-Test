# 齐论人才管理系统开发交接（2026-10-11）

此包用于已有项目的协作开发。最新业务代码以本包 Git 提交及 `01_Codex接手说明.md` 顶部为准；README、迁移说明和旧发布脚本中包含历史状态，不能据此重建线上项目。

## 包内内容

- `source/`：完整当前受版本管理的前台、后台、H5、简历插件、计分引擎、规则、15份SQL迁移、测试、部署脚本、页面/Logo/SVG资源及历史需求文档。
- `source-history.bundle`：本地Git所有分支和提交历史，可在离线环境克隆；本项目没有配置远程仓库。
- `runtime-assets/gh-inference-v1/model.json`：固定成品测评运行参数，SHA256与现有规则锁定值一致。是内部项目运行资产，不包含生产账号/业务数据库；仅交给获授权开发成员，保持原文件不改。
- `connections/`：已核实的服务器连接参数、SSH主机公钥、当前systemd/反向代理/证书续期配置、生产环境字段模板（秘密值占位）。
- `install-runtime.mjs`：只把固定模型安装到指定本地项目，已存在且不一致则拒绝覆盖。
- `manifest.json`、`SHA256SUMS.txt`：代码版本和逐文件完整性校验。

已有生产业务库、答卷、会话、账号密码、SSH私钥、生产加密密钥、IAM秘密、智能体令牌以及历史私人原件不在协作包中。源码和模型足够建立新的独立本地开发环境。用户要求交付全部开发与服务器信息，因此另附私密连接包，包含现有SSH密钥、实际生产配置及项目智能体令牌。该包仅交给负责服务器的获授权成员；连接、密钥安装和配置位置见 `connections/服务器连接与部署.md`。

## 从零启动协作者自己的本地环境

要求 Node.js 24.x（线上镜像24.19.0）和npm；若要保留分支历史，还需要Git。不要复制负责人已有`.env`或数据库。以下命令从解压包根目录运行：

```sh
# 推荐：从离线Git包恢复完整历史，创建协作者独立checkout。
git clone -b codex/development-handoff source-history.bundle project
# clone自动创建的origin指向本地bundle；它不是团队远程服务器。
git -C project remote remove origin
node install-runtime.mjs project
cd project
npm ci
npm run init
npm run build
npm run dev
```

打开 `http://127.0.0.1:3100`。首次本地初始化生成独立加密密钥、本地组织和local-admin账号，随机密码在该checkout的`.local/initial-access.txt`；不在交接文档中提供固定密码。`npm run init`只允许本地环境，不重置已有账号。若只需查看/运行源码，也可跳过Git克隆，执行`node install-runtime.mjs source`后在`source/`运行同样的npm命令。

不需在本地配置生产统一登录。默认本地密码登录；线上则使用 `https://zh.iqilun.cn` 统一账号。生产环境模板不能直接用于本地。

## 验证与协作

```sh
npm run build
npm test
node --experimental-strip-types deploy/verify-qilun-standard.mjs
```

测试用内存/临时数据库，不用生产库。某些历史核验依赖私人原件，会跳过或需要另行提供原件；`npm run verify:evidence`核对历史证据，协作包不包含迁移私人资料，不能把原件缺失解释为当前业务源码损坏。部分浏览器脚本指定macOS Chrome路径，其他平台需配置当地浏览器后再运行。

AI有model和external_agent两种工作模式。线上是external_agent，唤醒Webhook目前空；普通测评固定计分不依赖AI调用。本地默认model但不附付费供应商密钥。需要验证外部智能体时用 `tests/helpers/agent-fixture.ts` 的隔离环境及 `docs/agent-mode.md`；不要把生产写令牌写进源码。

每个协作者在自己的checkout创建`codex/`功能分支，完成相关检查后交付差异/提交。可由负责人提供团队远程地址后添加远程并推送；当前不能猜测GitHub地址。离线提交可用`git bundle create my-change.bundle HEAD ^<共同基线提交>`交回负责人，由负责人检查后合并。

生产发布先确认最新current、静态入口、业务配置和备份，再评估本次范围。`deploy/activate-*.sh`是已执行的一次性历史发布，不可拿来重复部署；新修改准备新的发布计划。仅前端修改通常新增哈希资源后原子替换入口并保留旧资源；API/SQL更新需保证单实例PGlite、停服快照及兼容回退。

原始证据不改写，已应用SQL迁移不改写；不重置数据库、账号或加密密钥。生产服务器还有其他项目，发布只作用于 `/opt/qilun-talent` 和rc站点，不能改全局服务或其他站。
