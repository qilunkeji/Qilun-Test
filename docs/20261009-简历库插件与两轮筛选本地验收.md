## 交付与操作演示

插件包：output/resume-extension/qilun-resume-extension-0.1.0.zip。解压后在 Chrome 扩展管理开启开发者模式，加载包含 manifest.json 的目录。详细说明见 apps/resume-extension/README.txt。

本地内存演示：运行 Node 24 的 scripts/demo-resume-library.ts，打开 http://127.0.0.1:3101/resume-library；账号 talent_lead，密码 demo-resume-local。这些是虚构演示账号，不是生产凭据。进程退出数据全部丢弃，未读取 .env 或生产库。

1. 网页“插件授权”填实际扩展 ID，生成一小时仅导入凭证；插件填本地地址和凭证。
2. 自行登录 BOSS，复制有权处理的文本或导入获准下载的 UTF-8 TXT。插件点击“收集当前简历”，预览再确认导入。没有平台页面读取许可时不读取 DOM，不自动采集、不翻页。
3. 简历库选一至三份虚构简历，选择“虚构岗位”版本，招聘要求填“必要条件：独立完成目录清单，并核对链接”，勾选本次外部处理授权。
4. 提交后第一轮左侧待看；明确不符项默认折叠，可展开核对；中间原文、右侧结论与打码引用。
5. 点击“进入第二轮”，保留材料分为建议重点看、需要补充确认；未完成或失败另列，不强制不符比例。
6. 填确认理由，点重点沟通、补充资料或暂不推进；刷新仍保留轮次和历轮人工记录。回到 BOSS 仅新开网页，不操作 BOSS、不发消息。
7. 同一简历可换其他岗位再次提交，新增独立批次与任务，不改旧结果或简历。

演示中的自动领取者是明确标注的本地模拟智能体，只验证协议和交互；不是实际 Grok 分析，也不用于验证招聘判断质量。没有唤醒配置时正式队列依赖外部智能体巡检；“约15分钟”是交互提示，不是本系统可以保证的完成时限。

## 复用与新增接口

- 保留 /api/v1/talents/imports、/resumes/:id、项目分类及招聘申请接口；导入逻辑抽成共用函数，不按姓名匹配。
- /api/v1/resume-library：检索简历版本、来源、项目、期限；/:id/delete：确认删除，申请引用返回409，取消关联任务并清理本筛选快照与结果。主档、其他版本、备份和下载副本不在删除范围。
- /api/v1/resume-extension/grants：本人生成、查看及 /:id/revoke 撤销短时授权；服务端仅存hash，角色撤回立即失效。
- /extension/v1/imports：独立插件 Bearer 导入边界，仅POST；不允许读取简历库、发任务、任意绑定人员或使用智能体写 token。
- /api/v1/resume-screens：提交固定岗位版本、此次要求和简历版本列表。每份一个独立 resume_job_screen 任务。
- /resume-screens/:id：轮次、结果、状态及历轮人工记录；/:id/round：进入第二轮；/items/:id/evidence：打码后的固定证据行；/items/:id/review：带revision的人工确认。
- /mcp/agent：复用现有十工具，list_task_types 动态返回新类型规则与严格schema；不新增模型调用，不复用 resume_review。原有业务任务保持不变。

任务材料只含一个岗位固定版本、一份简历固定版本和这次招聘要求；先按既有规则隐去电话、邮箱、身份证、微信。队列只放指针及计数，唤醒只用既有六字段，不含材料正文。证据按单行编号，不允许跨行引用。

## 新任务结果示例

假设 E1 为岗位证据“必要条件：独立完成目录清单”，E2 为打码简历证据“本人没有独立完成目录清单的经历”：

```json
{
  "recommendation": "clear_mismatch",
  "summary": "原文自述的经历与本次必要条件存在缺口。",
  "match_points": [],
  "gaps": [{
    "text": "原文自述缺少本次必要条件要求的经历",
    "citations": [
      {"id": "E1", "quote": "独立完成目录清单"},
      {"id": "E2", "quote": "没有独立完成目录清单的经历"}
    ]
  }],
  "unknowns": [],
  "follow_ups": ["是否有简历未记载的其他相关经历？"]
}
```

仅允许六个顶层字段。recommendation 三个指定值；summary 一句话且不含决策措辞；match_points/gaps 最多6条、follow_ups最多5条。每条引用必须是对应打码证据行3至500字的连续原文，缺口额外校验岗位与简历双证据。明确不符至少一条有引用缺口，重点建议至少有一条匹配证据；不足用需要补充确认。引用/schema校验失败不落结果，租约仍在，可修正重交。引用真实性由服务端验证，引用是否足以支持语义判断仍需人核对。

## 与线上差异、待验收

本轮没有服务器复核或部署。线上状态沿用接手文档历史记录（20261008-public-entry-v2、012迁移）；不是本轮实时线上检查结论。新增插件、简历库入口、resume_job_screen和013/014两项追加迁移目前仅在本地。待用户明确“上线”才能备份shared、运行隔离候选、迁移和切换；不能重跑旧的一次性激活脚本。

实际Chrome加载扩展、原生权限弹窗、企业BOSS许可和真实外部智能体处理质量仍需验收。未证明平台允许页面读取，因此这一版明确采用粘贴/获准TXT，不声称自动读取已完成。公开找到的[BOSS2019历史协议](https://www.zhipin.com/web/common/protocol/protocol-2019-09-30.html)第4节第8项限制未经许可第三方工具获取服务；不能当作当前企业许可。仅看见简历不等于获准长期保存或外传。

真实智能体需通过现有 list_task_types 获取 resume_job_screen 规则并遵循新结构。生产Webhook保持原样，本轮没读取或写入真实token，也未提交任何真实候选人材料。
