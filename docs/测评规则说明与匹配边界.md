# 测评规则说明与完整匹配边界

更新：2026-09-17。本次把可确认规则写为服务端 TypeScript，并增加后台「测评规则」页。这里的“规则”指材料支持的计算/展示行为，不把样本报告文字当成后台源码。

## 结论

**现有资料可以做报告展示层的部分计算一致性核对，不能据此完成原版“作答到岗位总匹配”的端到端复现。** 如果后续提供完整、可使用的题库、计分表、标准化、岗位建模、正式匹配和真实样本，可以按版本继续实现与回归。不能提前承诺未知规则全域 100% 相同。

当前完整链路的状态：

| 输入/环节 | 现有证据 | 实现与边界 |
|---|---|---|
| 题目 → 选项编码 | E2；真实取到三个题号 | 已实现编码与选择/排序校验；不是完整题库 |
| 答案 → 原始维度 | 没有逐题计分键 | 不执行，不由 LLM 补齐 |
| 原始维度 → 标准分 | 未取得转换与常模 | 不自动当百分位或任职成功概率 |
| 已有结果 → 展示衍生 | E1/E5；新增 PDF 输出 | 已实现明确公式；保留平局与模板差异 |
| 标杆 → 岗位模型 | 只知道输入1–5名优秀人员 | 聚合方法未知，不假定均值 |
| 个人分/岗位模型 → 分项匹配 | 有未使用的辅助函数 | 不以辅助函数冒充正式算法 |
| 分项 → 综合匹配 | 前端直接取服务器返回值 | 权重、门槛、舍入未知，不平均、不猜测 |
| 岗位能力审阅 | 可根据任务、技能、作品、面试证据实现 | 独立招聘工作流；不以MBTI/人格偏好排序或决定去留 |

## 1. 编码与价值观协议

依据 E2 §二：A/B 双陈述按可见顺序编码 `1,2,3,4,5`；单陈述从完全不符到完全符合编码 `5,4,3,2,1`。输入位置必须是整数0–4。

价值观：64个唯一词ID，4组各16个 → 每组选择5个 → 从20个中选10个 → 保存可见排序的名次1–10。代码拒绝重复、越组和未选择词。**没有词库与名次—维度计分权重，不能计算价值观分数。** 排名不能默认按10到1反向给分。

## 2. 四组动机

依据 E5 §四.A、E1 §四.2：

```text
安乐 = 享受 + 健康
归属 = 情感 + 荣誉
权利 = 权力 + 财富
成就 = 工作 + 创新
```

取最高合计的组。权利是标签，权力是维度，保留原区别。**当前实现返回所有并列最高组**，与原页面只显示一个标签可能不同；这是明确保留未知，而不是宣称完全相同。

## 3. PC 人才报告

适配器 `gh_talent_web_v81`，依据 E5 §四.B：

```text
W = Number(((财富+工作+创新+荣誉+权力)/25).toFixed(2))
L = Number(((健康+享受+情感)/15).toFixed(2))
D = W - L

abs(D) <= 1       k = 0.2
1 < abs(D) <= 5   k = 0.3
5 < abs(D) <= 10  k = 0.4
abs(D) > 10      k = 0

I = D*(1-k) + W*k
```

先分别舍入 W/L，再作差。末段回0保留，不“修正”为更大的权重。PC的 I 分档配置未取得，返回 `null`；没有用手机阈值补位。PC试算不自动生成工作/生活标签。

`pc_motivation_report_values` 是本系统明确命名的适配输入，并非已经确认的原站 API 字段。PDF图表数值只作为手工核对输入，来源接口、量尺关系与模板版本仍待核实。

## 4. 手机高级报告

适配器 `gh_phone_senior_v81`，依据 E1 §四：

```text
来源必须是 type4Result，而非图表使用的 motivationForAll
W = Number(((财富+工作+创新+荣誉+权力)/5).toFixed(2))
L = Number(((健康+享受+情感)/3).toFixed(2))
D = W - L

D > 1：工作倾向；D < -1：生活倾向；其余：兼顾
I = D*(1-k) + W*k，k同上述分段
```

只有显式选择 E1 2026-09-16 手机模板才使用：

| 指标 | 分档（从低到高） | 模板参数 |
|---|---|---|
| I | <0；[0,3.6)；[3.6,6.1)；≥6.1 | 21.6,6.1,3.6,0 |
| S（8项合计） | <257.5；[257.5,375)；[375,472.5)；≥472.5 | 637.5,472.5,375,257.5 |

21.6/637.5参与原页面最高档指针换算，不是岗位权重。本次只实现分档，不实现像素指针；模板值不能推广到所有账号。这里的适配器要求八个命名维度完整，原前端遍历数组时未作同等校验，这是本系统明确增加的输入约束。

## 5. 其他已有展示规则

- 外部已有匹配分：综合分85/70/50，分项80/70/50，分别对应原文显示等级。只格式化外部已有分数，不生成分数，也不接自动录用/淘汰。
- 职业风格：比较 E/I、S/N、T/F、J/P 已有极分数；任一对平局则类型为 `null`，不猜测原站平局选择，不生成岗位建议。
- 才干类别：按输入顺序前16项按类别加和，去掉零和类别；不自行排序取最大16项。PDF仅显示34项名次，不足以恢复加权占比使用的全部 value。
- 固定参考线 `[20,20,20,20,20,0]` 仅作历史证据，不生成“实时全站大数据平均值”。

以下**没有投入正式引擎**：getSingleMatch的85分辅助函数、历史文稿的6-x示意、虚构加权距离、人格招聘排序。报告中“思维模式/管理偏向/动机类型/动机组合”有具体输出文本，但条件分支与完整词典缺失，不能根据几个案例反推出唯一规则。

## 7. 后续规则应提供什么

优先提供原系统导出的机器可读配置；Excel/JSON/文字表格都可，关键是内容完整、逐条可定位：

1. 量表/题库版本、授权与用途、完整题目和选项、分组/排序约束。
2. 每题每选项到各维度的计分表、正反向、权重、缺答、超时、平局规则。
3. 原始分转换与常模版本、范围和质量校验。
4. 岗位模型输入样例与标杆聚合正式公式。
5. 分项匹配、总分组合、阈值、惩罚、截断、舍入顺序。
6. 完整解释词典、触发条件、报告模板及PC/手机差异。
7. 同版本完整答案和相应维度/模型/匹配输出的真实脱敏黄金样例，包含边界与缺失情况。

提供后按上述缺项逐项实现、验证、审批；只有代码实际执行并与样本核验过，才解锁相应能力。前端声明已齐全或几份PDF“看起来接近”都不会解除服务端阻塞。
